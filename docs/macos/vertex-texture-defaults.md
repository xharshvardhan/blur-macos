# Native vertex texture defaults

MAC143 belongs to the native FX adapter. The MAC139/MAC143 real-game draw reaches `C_MainView::RenderWithAA` through a WorldRender model instance, then rejects vertex shader589, slot1: expected original resource type3 (2D), actual4 (volume). The pure-SB capture has no evaluation errors and identifies the actual storage as exactly `FX::g_pFXDefaultVertexTexture`, the initialized1×1×1 RGBA32F zero default. The captured shader's BMSL metadata independently declares `DamageVolumeTextureSampler3d` at0 and `DamageInfoTextureSampler` at1. Private evidence is `_work/runtime/verification/mac143/texture-proof.json` and `shader.bin`; no original payload bytes are included here.

`System::OnEffectLoad` assigns the generic white2D default to all sampler parameters. `Context::SetVertexTexture` previously changed every vertex use of that pointer to the zero3D default. This loses the sampler's declared dimension. The PC DX11 mechanism already narrows the substitution: `NativeFX11.cpp` classifies only `g_sVehicleDamageVolumeTexture` as `damageVolume`, then applies the zero-volume helper only for that parameter. Ordinary2D samplers preserve the white2D default.

The native shader now exposes `C_VertexShader::GetTextureType(slot)`, which returns its actual reflected original resource type, or `~0U` when undeclared/uncreated. FX obtains the active vertex shader in `Context::Prefetch`, before binding parameters. Its native `SetVertexTexture` calls the existing default-volume substitution only for a reflected3D slot. Windows code, sampler state, parameter disk layout, shader blobs and all nondefault explicit texture pointers stay unchanged. Lower Metal draw validation still rejects missing or dimension-incompatible explicit resources; this does not select a substitute for an explicit binding.

## Required-resource boundary

This correction preserves existing FX default policy; it does not prove every required car parameter is bound. Original `VehicleActor` setup explicitly requests a damage layer, and `VehicleModel` requires its native damage setup and both real volume3D/info2D resources. `VehicleModel::SetParameters` supplies both through per-instance handles, or the existing shared-parameter path when a handle is absent. The actual captured draw proves an incorrect default substitution, but does not establish why that model instance still uses a default or whether a later binding should have supplied a real info texture. That per-instance ownership/data-flow remains unverified. No optional-asset classification, fixed sampler-slot assumption, or missing-texture fallback was introduced.

## MAC146: shared binding order and cache validity

MAC145's coherent game advances past the first corrected2D slot, then fails on slot0: the same shader589 expects3D and receives the generic white2D default. MAC146's pure-SB capture confirms current FX shader589, and the slot's storage identity is exactly the default2D owner. A bounded default-bind trace proves `RenderingData::Context::SetNode` → `BindSharedParameters` → `ApplyBinding` → `SetVertexTexture` before the eventual pass selection, first with no selected vertex shader and later with shader403. These are private diagnostic artifacts under `_work/runtime/verification/mac146/`; the trace does not require guessing material or car resource formats.

The source order explains the cache boundary. `RenderingData::Context::RenderList` calls `SetNode`, which applies node-wide shared bindings before `SetEffect` invokes `BeginPass`. A shared binding's source/register-valid bit then remains current even when `BeginPass::Prefetch` selects a shader with a different sampler dimension. The MAC143 per-bind dimension query was correct, but it had been asked against the preceding shader, and the already-current bit skipped a second bind. A generic source/register cache cannot certify this shader-dependent fallback materialization.

The native `BeginPass` now rematerializes every shared vertex sampler used by its selected pass from the context's live shared parameter data, after `Prefetch` and the normal bindings. It also does this on a conflict-free cached pass entry. It preserves local immediate values on that cached path: nonshared immediate texture values intentionally are not copied to the effect defaults. If a node introduced shared bindings that actually conflict with the current pass's recorded mask, the full existing pass path must run instead of the cached early return; this restores overwritten local bindings and follows the original `BindSharedParameters` comment's reapply requirement. Constant/register caching remains in use when there is no actual conflict. Native invalidation clears the selected vertex shader pointer along with the pixel pointer. No header, object layout or Windows path changes are needed.

The authored fixture extension registers actual original SharedEffect records, then uses explicit authored pass usage/conflict masks for those records. It exercises node bindings before any shader, a preceding2D shader, cached shared usage, explicit shared immediates, foreign-node conflicts, preservation of nonconflicting local immediates, restoration of local defaults after a real node clobber, strict explicit-dimension rejection/retry and invalidation without losing shared logical data. Cached-entry sequences stay inside one actual scene; the original display `BeginScene` resets lower state, so a new scene requires the fixture's normal FX invalidation, just as a fresh game rendering context does.

MAC146 source/fixture compilation in all four native configurations passes. The final expanded original SharedEffect/FX fixture passes real Debug GPU rendering/readback and complete process/static teardown under `MTL_DEBUG_LAYER=1`. An isolated adapter retaining the MAC143 dimension query but removing MAC146 rematerialization/cache handling reproduces the new actual primary: `stage=vertex slot=0 expectedType=4 actualType=3` at the first shared default draw; baseline exception unwind then hits its resource-list assertion (wrapper251). It is a failing differential, not clean baseline cleanup. Positive and differential logs are `_work/build/macos/physics-agent-vertex-default-macos/runtime.log` and `physics-agent-vertex-default-macos-pre-shared-fix/runtime.log`. No further game run or shared build was performed by this agent. This ordering correction does not prove why an individual real car model instance retains default damage data, and does not make missing required resources optional.
