## What the vehicle reports actually inspect

`CreateCollisionMesh` receives the already loaded model description and builds physics shapes from named elements/import-shape descriptors. The new vehicle-to-vehicle mesh and main world collider have separate active success bits. The disabled object-collider path leaves `m_ObjectColliderIndex=-1`; its later consumers test that sentinel before accessing a shape. The `NoDObjMesh` notification lives in a non-Gold automation block and is not a render-resource acquisition result. No platform guard makes its bit1 setter active on Windows while disabled on native.

`SetupDynamicMaterials` iterates all models/elements except names containing `_bone`. It calls `SetMaterial` for `g_vDamageSettings`, `g_vRenderSettings` and `g_vRenderColour`, explaining three repeated licenseplate notifications for the same element. `SetMaterial` reports the invalid location before allocating or assigning the corresponding per-part material controller. The parser/guard is shared code, without a native/console branch at this boundary. This audit does not establish whether the source's naming convention matches every retail hull element or whether those elements have active drawable material parameters. It therefore supplies no authority to strip `_hull`, attach them to another part or substitute a default material.

The required model-loading contract is elsewhere: VehicleActor's resource callback requires its main model resource, and requires the separate wheel resource only when `m_LoadSeparateWheelModel` selects it, before invoking `Create`. `C_VehicleModel::Create` has native required render-layer creation checks and acquisition rollback. These contracts must remain truthful; their existence does not prove that every possible required resource failure is covered, and these legacy notifications are not suitable replacements for their return status.

## AI timing and evidence boundary

`AmaxAIR::PostInitialise` broadcasts its actual AllLoaded/LoadFailed result based on track/system pointers and data/system initialization, without the later simulation-safe flag. `RaceLogicCore` transitions through POST_INITIALISE and TELL_THE_WORLD before normal race streaming enables simulation. `AllOK` intentionally includes simulation permission for update/collision/query consumers. Querying it as an asset-only check is broader than checking loaded track data. A previous MAC114 audit already recorded this same timing distinction; MAC245 reconfirms it against the frozen selected source rather than inventing a new failure policy.

No notification-to-live-resource capture was taken here. The exact phase flags for each232/243 warning and whether the legacy analysis latch influences a particular reachable race consumer remain unverified. Actual232 completed genuine ordered three-lap human progress before its independently confirmed photo-scene failure; that is meaningful gameplay evidence, but it does not certify all AI opponents or every cosmetic material.
