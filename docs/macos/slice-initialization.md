The matrix records the audited failure classes; the source-frozen section below states the subsequently applied narrow fixes. Neither is proof that the slice runs.

## Implementation grouping

1. **Required level/vehicle readiness closure:** check the real level pointer/wait result, preserve asynchronous pending states, fail definitively failed actor/model/physics loading through a thread-safe error handoff, and decouple readiness from one-shot logging. No simulation cadence changes.
2. **Transactional world/effect ownership:** scoped loader pauses, actual substage cleanup/rollback, and required renderer return values. Coordinate the same failed-layer state contract across application/world/actor boundaries instead of adding null-success guards.
3. **Selected graph conformance:** original postprocess/light/vehicle graph under Metal validation, real reflected shader/sampler/constant layouts, format/size/alias checks, temporal-buffer rotation and complete retirement. Avoid disabling passes to claim a working frame.
4. **One actual slice proof:** original Debug launch, confirmed debug screen, normal Return, actual Brighton load, one real BMW with keyboard input, completed real lap/race/finish, then clean exit. This proof is separate from compile, socket, serializer, layer and GPU unit fixtures.

An async callback or actor job must not throw blindly across a scheduler/resource worker. Publish its actual first failure through the native application's checked main-thread handoff. A loading wait needs no invented timeout or fabricated success; it needs a reliable distinction among pending, loaded and failed.

- Native AmaxWorldLayer::Create checks the real level pointer and WaitForResourceData bool, logs the exact path and returns E_FAIL after releasing its level handle/LUT/advertising ownership. This runs before allocating GameWorld; it does not claim rollback of every later world substage.

## MAC122 companion audit: pending, successful, and optional are distinct

The current real game enters original in-game BeginFrame; the next observed failure is FX render ownership in the blob-shadow model pass (MAC124), rather than another archive decode. MAC123 separately addresses discarded registered-renderer bool results and explicit completion of level actor-list creation. Original E_OnFail_Continue is intentional and remains the per-list policy: draining a list is not proof every optional actor succeeded, and cancellation/destruction is never itself successful completion. Required vehicle/RLC checks are separate. No mandatory subset of all level props has been recovered.

Global preloads need equally careful classification. GameAppResources.cpp particle texture preloading is an opportunistic retained cache: failed texture loads are discarded, and actual resource consumers may load separately. UserParticleLibrary::Open's result is discarded, but Generic/XtInterface.cpp has an explicit original mesh-name-missing policy (log warning and select Cube). This is an existing original fallback, not permission to introduce a new native substitute. A blanket failure of every preload would change original policy without establishing which selected effects require it.

The SpecialFX resource bag's IsWaitingForLoad records pending notifications, not successful data; ResourceBag::GetResourceBase returns a resource only for DataReady. CachePostBootFxResourceBagReady and WaitForBootResources currently wait for completion only. Bags can contain optional effects for other events. A global bag-wide fatal policy is therefore not justified by this audit; selected required consumers still need initialization status validation. This remains an explicit audit limitation and cannot be counted as complete required-resource proof.

Do not reinterpret Scene::UpdateStreaming false as a failed load: its source contract says whether data is still loading. False is completion. PhysicsLevel's ignored actual Import status is under MAC125, where that original bool and ownership must be verified before native propagation changes.

MAC123 companion audio classification: the original root.pak filename table contains concrete-fence/alarm BAFs but not their requested audio/dat/*.dat names; it contains audio/dat/do_metal_alloyrim.dat rather than the requested po_metalalloyrim.dat. These requests originate in dynamic-object cache lists. The filesystem OpenParams default supplies the word critical, so that log text alone does not identify a required startup boundary. This is an original data/reference mismatch requiring an audio-consumer audit, not evidence for changing path casing or replacing files. No audio policy/data change or complete audio claim follows.
